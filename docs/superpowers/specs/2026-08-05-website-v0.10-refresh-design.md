# Website v0.10 Refresh Design

**Date:** 2026-08-05

**Status:** Approved

## Goal

Bring the website up to date with Sessions Chronicle v0.10 without redesigning
the existing landing page or changing its central product message. The refresh
must introduce GNOME Activities search on the landing page and document its use
and privacy controls in the user guide.

## Scope

The refresh covers the landing page and user guide:

- Keep the hero, primary message, navigation, visual identity, and four existing
  feature cards unchanged.
- Add one full-width GNOME Activities search card below the existing feature
  grid.
- Add one GNOME Activities screenshot. Existing screenshots remain unchanged.
- Add a dedicated system-search section to the guide and link it from the table
  of contents.
- Update the landing-page description metadata to mention that indexed sessions
  can be found from the app and GNOME Activities.

This work does not redesign the site, renew the existing screenshot set, or add
new interactive behavior.

## Landing Page

### Feature card

Add a fifth feature card below the existing two-column grid. The card spans the
full grid width on desktop so the five-card composition looks intentional and
the horizontal GNOME Activities screenshot has enough room.

The card contains:

- Title: **Search from GNOME Activities**
- Copy explaining that users can find an indexed session from the Activities
  overview and open it directly in Sessions Chronicle.
- A new horizontal screenshot showing session results in GNOME Activities. Save
  it as `website/src/assets/screenshots/gnome_activities_search.png` and use
  non-sensitive demonstration content rather than personal session text.

The card follows the existing Adwaita-inspired visual language. Its desktop
layout places copy and screenshot side by side. On narrow screens, they stack in
one column without horizontal overflow.

### Existing content

The current feature cards remain unchanged:

1. Search every transcript
2. Inspect tool calls
3. Pin sessions worth keeping
4. Track your habits

The hero and its product promise also remain unchanged. This is a product-content
refresh rather than a conversion or visual redesign.

## User Guide

Add a **Search from GNOME Activities** section immediately after **Find a
session**, with a matching entry in the guide table of contents.

The section explains:

- Sessions Chronicle must be enabled in **Settings > Search** because the search
  provider is disabled by default.
- GNOME Activities starts returning session results after at least three
  characters are entered.
- Activating a result opens the indexed session directly in Sessions Chronicle.
- Results are limited to sessions already present in the local index.
- The first prompt remains visible as the result title.
- **Preferences > System Search > Show matching text in results** controls
  whether matching transcript excerpts appear in Activities.
- Matching text is hidden by default, while the first-prompt title remains
  visible in both modes.

The guide should direct users to **Settings > Search** when the provider is not
available and to the app's **System Search** preferences for excerpt privacy. It
must describe user-facing behavior without documenting the D-Bus architecture.

## Components And Assets

The implementation stays within the existing Astro structure:

- `website/src/components/sections/AtlasGrid.astro`: add the full-width card and
  responsive styling.
- `website/src/pages/guide.astro`: add the table-of-contents entry and guide
  section.
- `website/src/assets/screenshots/gnome_activities_search.png`: add the
  non-sensitive GNOME Activities screenshot.
- `website/src/pages/index.astro`: extend the landing-page description metadata
  to describe system search accurately.

No new component, client-side script, route, or dependency is required.

## Accessibility And Responsive Behavior

- Give the new screenshot alternative text that describes GNOME Activities
  showing Sessions Chronicle search results.
- Preserve the existing heading hierarchy.
- Keep the new guide section reachable through a stable anchor.
- Stack the full-width card's content on mobile.
- Ensure the screenshot scales within its container without clipping essential
  result content or causing horizontal overflow.

## Error And Empty-State Guidance

The website is static and introduces no runtime error path. The guide covers the
relevant user-facing absence cases:

- If Sessions Chronicle does not appear in Activities results, verify that it is
  enabled in **Settings > Search**.
- Enter at least three characters before expecting results.
- Only locally indexed sessions can appear; indexing problems continue to use
  the guide's existing troubleshooting flow.

## Verification

Verify the refresh with:

- `npm run build` from `website/`.
- Desktop and mobile review of the full-width feature card.
- Confirmation that the new guide table-of-contents link targets the correct
  section.
- Confirmation that the card and guide match shipped v0.10 behavior.
- Accessibility review of heading order and screenshot alternative text.
- A check for horizontal overflow at narrow viewport widths.

## Success Criteria

- A visitor can see that Sessions Chronicle supports GNOME Activities search
  without the landing page's existing message being rewritten.
- The fifth feature card looks deliberate rather than like an incomplete final
  grid row.
- A guide reader can enable system search, open a result, and understand the
  transcript-excerpt privacy setting.
- The site builds successfully and remains usable on desktop and mobile.
